# Порция — как поднять проект с нуля

Этот файл для человека, не для Claude Code. Пятнадцать минут по порядку.
Всё, что описано ниже, уже лежит в архиве — ничего дописывать не надо.

## Шаг 1. Проверить, что всё работает локально

Нужен Python 3.12. Из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Проверка ядра — она не требует токена и не выходит в сеть:

```bash
python3 -c "
from app.core import Profile, calculate
t = calculate(Profile('female',30,165,68,'moderate','cut'))
print(t.kcal, t.protein_g, t.fat_g, t.carb_g)
"
```

Должно напечатать `1840 136 61 187`. Если да — ядро цело.

Прогон покрытия, около 15 секунд:

```bash
python3 scripts/coverage.py --n 130
```

Ожидаемо: `План собрался: 130 (100.0%)`.

## Шаг 2. Создать репозиторий

Обязательно приватный: в `data/recipes.csv` лежит неопубликованный авторский
сборник.

```bash
git init
git add .
git commit -m "Порция: бот-планировщик питания, версия 1"
```

Дальше через сайт GitHub («New repository», **Private**) или, если стоит `gh`:

```bash
gh repo create porcia-bot --private --source=. --push
```

Проверьте перед первым пушем, что `.env` и `data/bot.db` не попали в
коммит — они перечислены в `.gitignore`, но лучше убедиться:

```bash
git status --short
```

## Шаг 3. Получить токен бота

В Telegram напишите @BotFather: `/newbot`, имя и username. Он выдаст токен.

```bash
cp .env.example .env
```

Откройте `.env` и вставьте токен вместо заглушки. Файл в git не попадёт.

Запуск локально:

```bash
export BOT_TOKEN=$(grep BOT_TOKEN .env | cut -d= -f2)   # Windows: задать вручную
python -m app.bot
```

Откройте бота в Telegram: `/start` → `/plan`.

## Шаг 4. Подключить Claude Code

Из папки проекта:

```bash
claude
```

`CLAUDE.md` подхватится сам. Первое сообщение можно дать такое:

> Прочитай CLAUDE.md. Это Telegram-бот, который планирует питание на день.
> Код версии 1 готов и проверен контрольными примерами, база рецептов
> заполнена, покрытие 100%. Ничего не переписывай и не рефактори.
> Первая задача: развернуть бота на Railway. Перед любыми правками в
> app/core.py или app/planner.py прогоняй контрольные примеры из раздела
> «Как проверять изменения» и показывай мне результат.

Дальше по документу «Деплой» из проекта Claude.

## Чего Claude Code делать не должен

Это в `CLAUDE.md`, но повторю — именно здесь чаще всего ломают:

- переписывать стек или «улучшать» архитектуру;
- добавлять ИИ в расчёты и подбор — в версии 1 его нет намеренно;
- смягчать ограничители по калориям и стоп-условия;
- расширять допуски по белку, если план не собирается;
- заполнять `portion_g` расчётом — там нужен замер готового блюда на кухне.

## Что в базе стоит перепроверить

Партии 2–4 (46 рецептов, `id` вида `b2-*`, `b3-*`, `b4-*`) посчитаны по
составу, расхождение с суммой по макросам нигде не больше 3,2%.

А вот это — восстановлено, не скопировано, и требует вашей сверки:

- **партия 1**, 18 рецептов, `id` вида `p1-*`. КБЖУ взяты из проектной
  документации, а признак штучности, теги и аллергены я проставил по
  названиям блюд. Сверьте с авторскими карточками.
- **16 продуктов**, `id` вида `pr-*`, и **12 добавок**, `a00`–`a11`.
  Собраны заново по справочным значениям. Состав набора выбирала не автор.

Пока это не сверено, покрытие 100% — обоснованная оценка, а не факт.
