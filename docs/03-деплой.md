# ТЗ для Claude Code: запуск бота-планировщика питания

Документ описывает поэтапный вывод готового кода в работающего Telegram-бота.
Код уже написан и проверен — задача не в разработке, а в развёртывании.

**Как пользоваться:** открыть папку `porcia-bot` в Claude Code и давать
этапы по одному, дословно. Каждый этап заканчивается проверкой; не переходить
к следующему, пока проверка не прошла.

Обновлён: 22 сентября 2026 — под собранный репозиторий: новое имя папки,
база 83 позиции, `.env` подхватывается автоматически, часть ограничений снята.

---

## Что на входе

Папка `porcia-bot`:

```
app/core.py         расчёт нормы калорий и БЖУ, ограничители, стоп-условия
app/planner.py      подбор дневного плана: перебор, масштабирование, добавки
app/db.py           схема БД и запросы (SQLite)
app/bot.py          хендлеры aiogram 3
data/recipes.csv    83 позиции (67 авторских рецептов + 16 продуктов)
data/addons.csv     12 добавок-гарниров
scripts/coverage.py прогон покрытия по сетке профилей
docs/               спецификация, контекст, база рецептов, этот документ
CLAUDE.md           контекст для Claude Code, читается автоматически
requirements.txt    aiogram==3.15.0, python-dotenv==1.0.1
runtime.txt         python-3.12
Procfile            worker: python -m app.bot
.gitignore          .env, .venv, data/bot.db исключены
```

Команды бота: `/start` `/plan` `/replace` `/profile` `/restart` `/delete`
`/help`, плюс постоянная клавиатура с кнопками «План на сегодня», «Мой
профиль» и «Помощь». Повторный `/start` профиль не сбрасывает — для этого
`/restart`..
ИИ не используется — расчёт и подбор детерминированные.

## Этап 0. Токен

Бот ещё не создан. В Telegram написать @BotFather: `/newbot`, задать имя и
username, получить токен.

**Токен никуда не вставлять в переписку и не записывать в файлы проекта.**
Он живёт в двух местах: в локальном `.env` (который в `.gitignore`) и в
переменных окружения Railway.

Если токен всё же куда-то попал открытым текстом — @BotFather → `/mybots` →
бот → **Bot Settings → Revoke current token**, и начать с нового.

**Проверка:** в папке проекта выполнить `grep -rn "AAH" . --exclude-dir=.git`
— не должно быть ни одного совпадения.

## Этап 1. Локальный запуск

**Цель:** убедиться, что бот отвечает, до всякого деплоя.

```bash
cd porcia-bot
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Вписать токен в `.env` в строку `BOT_TOKEN=`. Загружать вручную не нужно:
`main()` в `app/bot.py` подхватывает `.env` через `python-dotenv`, а на
Railway, где переменные приходят от платформы, импорт мягкий и не мешает.

Перед запуском бота прогнать проверку ядра — она не требует токена и сети:

```bash
python3 -c "
from app.core import Profile, calculate
t = calculate(Profile('female',30,165,68,'moderate','cut'))
print(t.kcal, t.protein_g, t.fat_g, t.carb_g)"
```

Должно напечатать `1840 136 61 187`. Если нет — ядро сломано, дальше не идти.

Запуск:

```bash
python -m app.bot
```

**Проверка.** В Telegram найти бота по имени и пройти сценарий:

| Шаг | Ожидаемо |
|---|---|
| `/start` → шесть вопросов | в конце приходит норма: ккал, Б/Ж/У, клетчатка, вода |
| `/plan` | четыре блюда с калорийностью (вместо граммов — «порция ×N», вес готовой порции не замерен), строка «К этому» с гарниром, итог по КБЖУ |
| кнопка «Другой вариант» | приходит другой набор блюд, итог по-прежнему в норме |
| `/profile` | параметры и норма совпадают с тем, что вводили |
| `/delete` → `/plan` | бот просит пройти `/start` |

Отдельно проверить стоп-условие: пройти `/start` с возрастом 16 — бот не
должен считать норму, вместо неё приходит текст о направлении к специалисту.

**Стоп-условие этапа:** все строки таблицы прошли. Если нет — чинить здесь,
а не после деплоя.

## Этап 2. Репозиторий на GitHub

**Цель:** код в приватном репозитории, без секретов в истории.

```bash
cd porcia-bot
git init
git add .
git status          # ОБЯЗАТЕЛЬНО: убедиться, что .env и data/bot.db НЕ в списке
git commit -m "Порция: бот-планировщик питания, версия 1"
```

Если `.env` попал в список — остановиться, проверить `.gitignore`, выполнить
`git rm --cached .env` и закоммитить заново.

Создать **приватный** репозиторий и запушить:

```bash
gh repo create porcia-bot --private --source=. --remote=origin --push
```

Если `gh` не установлен — создать репозиторий на github.com вручную
(обязательно Private) и запушить по инструкции со страницы репозитория.

**Проверка:** открыть репозиторий на github.com — `.env` отсутствует,
`data/` содержит только `.csv`.

**Важно про приватность.** Репозиторий должен остаться приватным: в
`data/recipes.csv` лежит собственный авторский сборник — неопубликованный
контент, на котором стоит платный продукт. Публичный репозиторий = бесплатная
публикация всех рецептов.

## Этап 3. Деплой на Railway

**Цель:** бот работает без включённого компьютера.

1. Зарегистрироваться на railway.app через GitHub.
2. **New Project → Deploy from GitHub repo →** выбрать `porcia-bot`.
3. Дождаться первой сборки. Она **упадёт или будет перезапускаться** — это
   нормально, переменной `BOT_TOKEN` ещё нет.
4. Открыть сервис → вкладка **Variables** → **New Variable**:
   имя `BOT_TOKEN`, значение — токен от @BotFather. Сохранить.
5. Railway пересоберёт сервис автоматически.

**Важно:** перед этим остановить локальный запуск (Ctrl+C). Два процесса с
одним токеном одновременно опрашивать Telegram не могут — второй получит
ошибку `TelegramConflictError: terminated by other getUpdates request`.

**Проверка:** вкладка **Deployments** → логи показывают `Start polling` без
трейсбеков. В Telegram `/start` и `/plan` отвечают.

**Стоп-условие:** бот отвечает при выключенном компьютере.

## Этап 4. Постоянная база данных

**Цель:** данные пользователей не исчезают при обновлении кода.

Сейчас данные в SQLite-файле `data/bot.db`. На Railway диск контейнера
эфемерный: **при каждом редеплое все профили и планы стираются**. Для
прототипа на себе это терпимо, перед живыми пользователями — нет.

Два пути, выбрать один.

**Путь А — быстрый, Volume.** Railway → сервис → **Settings → Volumes →
New Volume**, путь монтирования **`/app/var`**. Затем на вкладке Variables
добавить `DB_PATH=/app/var/bot.db`. SQLite-файл переживает редеплои.
Минус: один инстанс, без бэкапов, плохо масштабируется.

> **Не монтировать том в `/app/data`.** Том приходит пустым и перекрывает
> каталог целиком, а в `data/` лежат `recipes.csv` и `addons.csv` — они
> исчезнут, и бот перестанет собирать планы. Для этого `db.py` и читает
> `DB_PATH` из окружения: по умолчанию база остаётся в `data/bot.db`, а на
> Railway уезжает в отдельный каталог.

**Путь Б — правильный, PostgreSQL.** Railway → **New → Database → Add
PostgreSQL**. Переменная `DATABASE_URL` появится автоматически. Далее
переписать `app/db.py`:

- заменить `sqlite3` на `psycopg` (добавить `psycopg[binary]` в
  `requirements.txt`);
- в `SCHEMA` заменить `INTEGER PRIMARY KEY AUTOINCREMENT` на
  `GENERATED BY DEFAULT AS IDENTITY`;
- заменить плейсхолдеры `?` на `%s`;
- `INSERT OR IGNORE` → `INSERT ... ON CONFLICT DO NOTHING`;
- `CURRENT_TIMESTAMP` работает без изменений;
- строку подключения брать из `os.environ["DATABASE_URL"]`, с фолбэком на
  SQLite, если переменной нет (чтобы локальная разработка не требовала
  Postgres).

Остальные модули менять не нужно — они обращаются только к функциям `db.py`.

**Проверка:** пройти `/start`, затем сделать любой коммит и запушить.
После редеплоя `/profile` должен показать те же параметры.

## Этап 5. Приёмка

Прогнать на живом боте и зафиксировать результат:

- [ ] женский профиль, цель «снизить» — план собирается, итог в пределах
      ±5% от нормы по калориям;
- [ ] мужской профиль, цель «набрать» — план собирается (здесь обязательно
      появится строка «К этому» с крупным гарниром — без неё мужская норма
      не закрывается);
- [ ] жиры в плане не выше 120% нормы — коридор по жирам закрыт в v1.2
      спецификации, и это легко сломать правкой допусков;
- [ ] «Другой вариант» четыре раза подряд — блюда меняются, одно блюдо не
      стоит дважды в одном дне;
- [ ] `/delete` реально удаляет: после него `/profile` говорит, что профиля нет;
- [ ] возраст 16 — расчёт не производится;
- [ ] `/plan` отвечает быстрее секунды;
- [ ] бот отвечает через час после последнего деплоя (не «уснул»).

## Известные ограничения версии 1

Это не баги, а осознанно отложенное. Не чинить на этом этапе.

**Масштаб порции общий на весь день.** Все блюда растягиваются одним
коэффициентом. В спецификации заложено индивидуальное масштабирование —
это первая доработка после запуска.

**Раскладка по приёмам держится штрафом, а не коридором.** Медианы сидят на
цели (завтрак 24% при 25%, обед 34% при 35%, ужин 30% при 30%), но хвосты
остались: обед до 48% дня, перекус до 20% при заложенных 10%. Жёсткий коридор
стоил бы покрытия — ±50% даёт 94.6%, ±20% — 80.8%.

**Тяжёлым профилям план находится не всегда.** Атлеты с нормами от 3350 ккал
упираются в допуск по жирам: их день должен иметь не больше 24% калорийности
из жира, а калорийных нежирных блюд в базе нет. Структурно непокрытых профилей
нет — на восьми seed план не получил ни один, но четверо из 130 получают его
не при каждом запуске, а живой профиль 188 см / 120 кг — в половине случаев.
Лечится одним новым блюдом, не кодом — см. `docs/06-база-рецептов.md`.

**Подбор не исчерпывающий.** При текущих пулах комбинаций 1 713 800 при
пороге 60 000 в `_combos()`, дальше идёт случайная выборка. Результат зависит
от `seed`.

**Граммовки у авторских блюд нет.** Вес готовой порции не замерен; бот
показывает коэффициент порции.

**Данные частично восстановлены.** Партия 1, продукты и добавки собраны по
документации и справочным значениям, а не из авторских карточек. Требуют
сверки владелицей проекта.

**Нет дневника, разбора текста, напоминаний, оплаты.** Второй и третий круг.

**Markdown-разметка хрупкая.** Если в новых рецептах появятся символы
`_ * [ ] \``, Telegram вернёт ошибку парсинга. Либо избегать этих символов в
названиях, либо перевести `format_plan` на `ParseMode.HTML` с экранированием.

## Типовые ошибки и что делать

| Симптом | Причина | Решение |
|---|---|---|
| `TelegramConflictError: terminated by other getUpdates` | бот запущен в двух местах | остановить локальный процесс, оставить только Railway |
| `TelegramUnauthorizedError` | неверный или отозванный токен | проверить `BOT_TOKEN` в Variables, без пробелов и кавычек |
| `KeyError: 'BOT_TOKEN'` | переменная не задана | добавить в Variables на Railway или в `.env` локально |
| Деплой «крутится» и падает | Railway ждёт веб-порт | проверить, что `Procfile` содержит именно `worker:`, а не `web:` |
| Профили исчезли после обновления | эфемерный диск | выполнить Этап 4 |
| `/plan` отвечает «Не удалось собрать план» | норма вне охвата базы | ожидаемо для атлетов на наборе от 3800 ккал; для обычных профилей — проверить, что `data/addons.csv` загрузился и в нём есть строка `a00` «Без добавки» |
| `can't parse entities` | спецсимвол в названии рецепта | см. «Markdown-разметка хрупкая» |
| `ModuleNotFoundError: No module named 'app'` | скрипт запущен не из корня | `scripts/coverage.py` сам добавляет корень в путь; для своих скриптов сделать так же |

## Что дальше, после запуска

Порядок доработок по убыванию ценности:

1. Сверить партию 1, продукты и добавки с авторскими карточками.
2. Одно калорийное блюдо 900–1100 ккал с долей жира до 25% — закроет
   оставшиеся 1.5% профилей. Замер — в `docs/06`.
3. Индивидуальное масштабирование порций.
4. Отметка «съел / не по плану» и пересчёт остатка дня — то, ради чего
   планировщик выигрывает у трекеров.
5. Напоминания по расписанию.
6. Подписка: три дня полного доступа, дальше платно.

Первые четыре не требуют ИИ.
